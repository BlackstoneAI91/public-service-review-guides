# Making a Print-Friendly Cover Page for a Wafer Scrap Collection Enquiry

A practical guide for Singapore procurement teams on building a readable, black-and-white-safe cover page for a wafer scrap collection enquiry, with a fictional worked example and a short print check.

Published by Blackstone Intelligence.

## Why the cover page carries the meeting

A cover page is the one sheet everyone at a meeting can hold at the same time. Before a discussion about a wafer scrap collection enquiry begins, that sheet should tell each reader what the pack is, who prepared it, when it was written, and which parts are still open. If the cover page does that, the rest of the pack can be read in any order without confusion.

Treat the cover page as a reading aid, not a summary of the supplier. It should describe the document set in front of the reader, not restate a company's capabilities. That distinction keeps the page honest and keeps it short.

For context, San Techno Pte Ltd is a Singapore-based company working in semiconductor and solar materials, silicon recovery, specialized power module development, and botanical extracts under the ST GREEN brand. A procurement team may be reading a public page such as the wafer scrap collection page while assembling its own internal handout. The handout belongs to the team, not to the supplier, and should say so.

A useful cover page answers four questions in plain text: what is inside, what is missing, what the reader should decide, and where to look next. Everything else is optional. Keep the tone neutral, avoid promotional language, and write for a colleague who has five minutes before the meeting starts.

## Text that still makes sense in black and white

Many meeting packs are printed on an office mono printer, so colour cannot be the only signal. Test each line by asking whether it would still read correctly if every shade became grey.

Labels beat colour. Instead of a red heading meaning "open question", write "Open question" in the heading itself. Instead of a green tick meaning "received", write "Received" or "Not yet received". A reader who prints in black and white, or who has low colour vision, then loses nothing.

Contrast matters more than hue. Dark text on a light background survives printing; pale grey text on white often disappears. Keep body text at a readable size and avoid thin fonts for anything a reader must act on.

Shading should carry meaning only alongside a word. If a table row is shaded to show a missing item, the row should also contain the word "missing" or a dash in a labelled column.

Finally, check that any highlighted phrase still reads as a phrase. A sentence that says "see the highlighted section" fails on a mono printout. Name the section instead: "see Section 3, Document status". This single habit removes most print surprises.

## Spelling out a link caption without relying on colour

A printed page cannot be clicked, so a link caption has to work as plain text. The common failure is a line that says "click here" in blue. On paper, the reader has no idea where "here" is.

Write the caption so it describes the destination in words. For example, a handout might include a line such as: "Public reference page: San Techno wafer scrap collection page, read on the date shown below." The reader can then find the page later without needing the colour or the underline.

Keep the caption short and factual. Do not add a web address to the body text if your house style puts addresses in a separate reference block; the application that assembles your pack can add approved links. What matters on the printed sheet is that the caption names the page and says why it is included.

If the caption refers to a supplier's public material, say so plainly. A neutral phrasing such as "supplier public page, included for reference only" prevents a reader from mistaking a marketing page for a specification.

Where a caption points to a page about silicon recovery or reusable raw materials for solar, keep the wording descriptive rather than evaluative. The cover page is not the place to judge the supplier.

## Where to write a missing document date

Undated documents cause quiet confusion. A reader cannot tell whether a page is current, and a meeting can spend its first minutes working out which version is on the table.

Give the date its own labelled line near the top of the cover page, not buried in a footer. Use a full date with the month spelled out, for example "Prepared: 14 March 2025", so it cannot be misread across regional date formats.

When the date is unknown, do not leave a blank. Write "Date not stated on source document" and add a second line for when your team received or printed it. That way the reader knows the difference between the source date and the handling date.

Apply the same rule to version numbers and page counts. If a page is missing from the pack, list it as missing rather than silently renumbering. A short "Document status" table with columns for item, date, and status handles this cleanly.

This is a documentation habit, not a legal record. If your organisation has formal records requirements, follow those; the cover page simply makes the gaps visible to the reader.

## A fictional worked cover page

The following is an invented example for illustration only. It does not describe a real enquiry, a real supplier response, or real terms.

Title: Wafer scrap collection enquiry, reading pack for internal meeting.
Prepared by: Procurement team, example company, Singapore.
Prepared: 14 March 2025.
Purpose: To give attendees a shared reading pack before discussion. This pack is internal and does not constitute an order, instruction or agreement.
Contents: Section 1, public reference page caption; Section 2, internal question list; Section 3, document status table.
Document status: Public reference page, date not stated on source, status received; internal question list, 12 March 2025, status draft; supplier reply, not yet received.
Open questions: which colleague owns the follow-up; whether the public page should be re-read before the next meeting.
Reference caption: San Techno wafer scrap collection page, public supplier page, included for reference only.
Contact line for internal queries: meeting chair, not the supplier.

Notice how the example avoids colour, avoids web addresses in the body, and states the missing date openly. It also keeps the supplier's role small: the pack is the team's document, and the public page is one reference among several. A reader who picks up this sheet cold can still tell what is inside and what is unresolved.

## A short print check before you circulate

Run this check on a mono printout, not on screen. It takes a few minutes and catches most of the problems a meeting would otherwise discover.

One: print one copy in black and white and read the headings. Can you tell which items are open without seeing colour? Two: look for any phrase such as "see highlighted" or "click here" and replace it with a named section or a descriptive caption. Three: confirm the prepared date is present, or that the missing date is stated in words. Four: check that the document status table lists every item in the pack, including anything not yet received. Five: read the purpose line aloud; if it sounds like a sales summary, rewrite it as a reading aid.

As a rough author heuristic, aim for a cover page that fits on one side of A4 with room to spare. If it spills over, move detail into the pack rather than shrinking the type.

Keep the language plain and the claims modest. The cover page does not need to describe the supplier's business; it needs to help a colleague read the pack. Where a public page is cited, describe it as a public reference and leave evaluation to the meeting.
